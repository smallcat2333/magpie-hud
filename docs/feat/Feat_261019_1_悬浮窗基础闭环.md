## 1. 需求

### 1.1 背景

来源：用户于 2026-10-19 提报，并提供桌面文件 `magpie-route-float-SPEC.md`。完整原文已归档到 [实现说明](../spec/magpie-route-float-SPEC.md)，本档案承接其中 M1。用户希望在 Claude Desktop 或其它 Agent 经 Magpie 完成请求后，无需打开路由页，即可查看最新命中结果。

项目位于独立目录 `magpie-hud`。当前只有上一轮创建的 Rust + CXX-Qt + Qt6 Widgets + WebView2 脚手架；最新技术栈已指定为 Tauri 2 + 系统 WebView，因此切换工程骨架属于本 FEAT 的开发工作。需求建档阶段不修改、删除现有代码，不将现有 RSQt 工程描述成已可运行的 Tauri 工程。

本 FEAT 只做新应用骨架与第一个最小闭环。M2 的三节点图和托盘见 [分流图与托盘](Feat_261019_2_分流图与托盘.md)，M3 的位置持久化与多屏约束见 [多屏与配置](Feat_261019_3_多屏与配置.md)。M1 是中间里程碑，M1+M2 才构成优先交付的可视化 MVP；完整验收还包括 M3。

已知约束：`usage.jsonl` 在请求结束时追加，因此本产品呈现已完成请求的路由结果，不承诺在请求刚发起时识别命中账号。完整排除原因可能不在文件里，必须按真实字段降级，不编造。

### 1.2 目标

使用 Tauri 2 与 Rust 建立 Windows 10/11 独立无边框置顶悬浮窗，只读 `%USERPROFILE%\.config\magpie\usage.jsonl`，启动读取尾部，后续实时显示固定两行带本地 `HH:mm:ss` 的路由说明。目标约 300ms，验收上限为完整记录写入后 500ms。

范围与数据口径：

- 窗口使用半透明深色底、中文文案，可拖动，失焦持续显示；上方为后续 M2 的图形区，下方是固定两行信息区。建议尺寸沿用 SPEC 的宽 720–900px、高 220–320px，具体布局在 §2 再定。
- Rust 使用 `notify` 监听写入、重命名与替换，50–150ms debounce 后只读尾部，读取上限采用 SPEC 建议的 64KB，不全量加载。启动取最新 1–2 条有效记录，按 `route_id` / `t` 去重，通过 `route-update` 发送结构化结果；前端不接收整个原始日志代替后端处理。
- 字段候选为 `t`、`agent`、`providerAccount` / `host`、`model` / `served` / `req`、`effort`、`ms`、`ttft_ms`、`in` / `out` / `cache_read` / `cache_write`、`status`、`route_id`、`session`。它们是待实机核对的外部数据，不预设所有字段必然存在；成功状态值、字段语义及请求模型与服务模型的对应关系在开发时只读样本确认。
- 第一行依据最新成功记录说明命中账号、服务模型、强度及可用统计，行首时间取该记录的 `t` 并转本地时间（当前用户环境 Asia/Shanghai）。Token 为 `(in + out + cache_read) / 1000`，显示一位小数 `k token`；缓存命中率为 `cache_read / (in + cache_read) * 100`，注明“估算”。只有字段齐备且分母有效时才展示相应统计，缺失不冒充 0。
- 第二行仅在有同次路由证据时描述强度变更，或展示有真实证据的其它账号跳过原因；不足时按 SPEC 显示带对应记录时间的“候补/其它账号未选中”占位说明，或 `—`。占位不能表达成已查明具体候补账号或排除原因；README 标明“完整排除原因待二期对接路由 API”。
- 有数据的两行各自显示对应 `HH:mm:ss`，长文本优先单行省略；信息槽固定两个，不堆积历史。时间缺失或无记录时显示明确占位，不伪造事件时间。
- 无记录显示“等待 Magpie 路由写入…”及监视路径；文件缺失提示“未检测到 Magpie usage.jsonl，请确认 Magpie 已运行过”；坏行和未写完的行不导致崩溃，有上一帧时保留有效内容并轻提示。外部文件替换、截断、重建后继续监视。
- 所有路径从用户主目录解析。只读 usage 文件，不读取 `logins.json`、API key，不依赖 HTTP API，不代理或改写请求，不修改/fork Magpie，不注入、抓窗或读进程内存，不合并进 rs_agent_router。

### 1.3 验收标准

- [ ] Windows 10/11 下以 Tauri 2 + 系统 WebView 启动独立窗口，具备无边框、深色半透明、置顶、拖动和失焦不关闭；工程目录保持 `magpie-hud`，不依赖启动 Magpie 主窗口或 AR。
- [ ] 启动能读取最新有效记录；通过测试样本和真实 `group/smart-split` 请求验证：完整日志记录落盘至界面更新 ≤500ms，目标约 300ms；连续写入不重复刷新相同记录，单次仅读取尾部 ≤64KB，重命名替换/截断/重建后仍可更新。
- [ ] 两个信息槽固定，正常记录每行含来源记录的本地 `HH:mm:ss`；第一行字段、token 与估算缓存命中率符合上述公式，第二行仅展示证据支持的说明或指定占位，长文本不撑成历史墙，缺字段与无效时间不伪造统计或时间。
- [ ] 空文件、文件不存在、缺字段、非法 JSON、尾部半行均不崩溃；空态文案和路径符合 SPEC，解析错误保留上一帧有效数据，后续有效记录能恢复；运行期间不读取密钥文件、不写 usage 文件、不调用路由 HTTP API。
- [ ] README 提供实际可执行的启动方法、`cargo tauri build`、默认数据路径、只读外挂关系及第二行降级限制；附运行截图，记录刷新延迟的实测方法和结果，不把尚未完成的 M2/M3 宣称为已完成。

### 1.4 初步路线

沿用独立项目目录，在开发阶段将现有 RSQt 构建入口切换为 Tauri 2 工程；方向采用 Rust workspace + `src-tauri/` + `ui/`，前端优先原生 HTML/CSS/JS，避免额外引入 React/Svelte。本轮只记录方向，具体文件迁移与任务拆解留到 §3。

Rust 侧负责文件尾部读取、事件合并、外部字段解析、去重和结构化事件；前端负责信息展示，窗口拖动/置顶优先使用 Tauri 的现有能力。启动快照与前端订阅必须能衔接，防止首次事件早于页面监听导致空白。已有 RSQt 模板不作为 Tauri 窗口/桥接实现复用。

开发前核对真实 jsonl 样本，仅提取所需字段，不读取账号密钥。先以独立 fixture 验证解析、半行/坏行、文件替换与公式，再在实际 WebView 窗口测量写入到渲染延迟；不通过修改生产 usage 文件制造测试数据。

关键风险为事件只在请求完成后可见、日志字段随版本变化、文件轮转导致重复/漏读，以及首次事件订阅竞态。M1 的基础窗口不替代 M3 的多屏与位置持久化验收。
