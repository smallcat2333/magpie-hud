## 1. 需求

### 1.1 背景

2026-10-21 用户要求 HUD 宽度、高度可分别调整，并随长宽比适配长模式和宽模式。原窗口不可缩放，启动还会把保存的尺寸抬回 1120×400，无法常驻在窄高空间。

### 1.2 目标

开启原生窗口缩放和无边框边缘/角落拖动。宽窗横向排列统计、来源、中枢与会话；窄高窗纵向排列统计、来源/中枢与会话列表。保留置顶、托盘和底部固定两行，正常退出后恢复尺寸。

### 1.3 验收标准

- [ ] 边缘与角落可以分别调整宽高，缩放时不固定比例。
- [ ] 1120×400、420×760、360×640 无横向溢出；会话和 Token/TPS 均可读。
- [ ] 长宽比小于 1.25 或宽度小于 680px 时使用纵向布局，其他情况使用横向布局；连线随实际位置重算。
- [ ] 正常退出后重启恢复用户尺寸，仍遵守工作区边界。

### 1.4 初步路线

复用 Tauri 原生 resizable、startResizeDragging、已有 WindowPlacement/persist_window/constrain_current；前端 ResizeObserver 根据尺寸选布局，不增加设置页。变更限于窗口配置、能力声明与原生 HTML/CSS/JS。

## 2. 原型（活文档：UI 设计贯穿始终，随 dev 演进）

### 2.1 设计总纲

保留现有石墨深色、系统中文字体和洋红路由标识。横向维持三节点；纵向将统计放顶部，来源和中枢并排，其下为带分支的会话列表。标题与本次数字先于账号细节阅读。

### 2.2 控件清单

| 控件对象名 | 类型 | 用途 |
| --- | --- | --- |
| `#hud[data-layout]` | 主容器 | wide / tall 布局 |
| `[data-resize]` | 八个边缘/角落命中区 | 调整原生窗口宽高 |
| `#route-lines` | SVG | 跟随列表和窗口尺寸画分支 |

### 2.3 交互说明

拖动边缘/角落进行原生缩放，顶部仍可拖窗。ResizeObserver 触发布局重排与连线定位；缩放不会更改会话选择和统计数据。
