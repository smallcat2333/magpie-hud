## 1. 需求

### 1.1 背景

2026-10-21 用户要求用会话名称代替八位 UUID，从 Magpie 源码寻找请求进行中的数据并显示流动动画，在会话块记录 TPS 和 Token。原 usage.jsonl 只在请求结束时追加，不能判断进行中状态。

### 1.2 目标

HUD 只读接入本机 Magpie 实时路由与活跃请求；会话块主行显示真实名称，次行显示账号、模型与强度，并显示本次 Token/TPS。请求正在处理时持续动画，完成或断线后停止。完成日志仍作为当日累计真源，进行中快照不重复入账。

### 1.3 验收标准

- [ ] 请求结束前显示真实活跃状态、账号/模型和流动连线；并发等待、完成和断线能结束活跃动画，减少动态效果时不播放动画。
- [ ] Desktop 当前/恢复/历史 CLI ID 按明确关系映射标题，改名可自动刷新；名称缺失显示未命名，不以八位 UUID 代称。
- [ ] 完成会话块显示本次 Token=`in+out+cache_read`、TPS=`out/(ms-ttft_ms)*1000`；无有效耗时或未提供用量时显示未知，不拿上次值当实时计数。
- [ ] 当日费用、次数和用量不会因为活跃快照重复累计；日志失败恢复与会话切换继续有效。
- [ ] 本地网关只允许回环 HTTP，不读取密钥、不修改 Magpie、不截取请求/响应正文。

### 1.4 初步路线

数据契约核对自 [yetone/magpie](https://github.com/yetone/magpie/tree/5c557c793cc888c1227989b7bce654f239dd8fce)：

- `internal/gateway/trace.go`：`/v1/magpie/trace?after=<seq>&wait=1` 长轮询，最长 25 秒；tries/done/order 表示路由尝试和终态。
- `internal/gateway/active.go`、`concurrency.go`：`/v1/magpie/concurrency` 的 active 完整集合与 slot/rpm/upstream 阶段。upstream 同时包含等待首字与流式返回，不能声称每个 Token 都已到达。
- `internal/sessions/desktop_titles.go`：Desktop 元数据 sessionId、cliSessionId、unarchivedCliSessionId、preClearCliSessionId、priorCliSessionIds 显式映射与冲突优先级。
- `internal/sessions/codex_titles.go`：`session_index.jsonl` 的 id/thread_name。

Rust `live.rs` 负责读取和展示合并，`Runtime.refresh` 仍合成唯一快照；日志游标与账本继续负责完成统计。使用 ureq 无 TLS/代理默认功能的同步 HTTP 客户端，在独立线程访问回环地址。活跃接口半秒刷新、标题两秒刷新。

当前 Magpie 未在 active 中提供执行中的精确输出 Token；会话块进行中显示“待统计 Token / — TPS”，最终记录到达后显示精确值。动画表示真实请求活跃，不伪造逐 Token 进度。

## 2. 原型（活文档：UI 设计贯穿始终，随 dev 演进）

### 2.1 设计总纲

主行：会话名称＋状态；次行：账号＋模型＋强度；右侧（纵向为第三行）：本次 Token/TPS。洋红流动分支只表示活跃请求，等待状态另有文字；数值使用等宽数字。

### 2.2 控件清单

| 控件对象名 | 类型 | 用途 |
| --- | --- | --- |
| `.session-title` | 文本 | 真实会话名称 |
| `.card-account` | 文本 | 缩略账号，完整值在提示 |
| `.card-metrics` | 文本组 | 本次 Token 与 TPS |
| `.branch.running` | SVG 路径 | 请求执行中的流动效果 |
| `#session-select` | select | 以真实标题选择完整会话 ID |

### 2.3 交互说明

请求活跃即显示，不等待 usage 追加；结束后替换为日志完成卡片。选择会话和点卡片继续同步统计与底栏。失联时停止活跃展示并保留已完成记录，恢复连接后继续更新。系统减少动态效果保留状态文字和静态分支。

### 2.4 UI 变更日志

- 2026-10-21 | 用标题替换 UUID 主显示，加入单次指标和由真实活跃状态驱动的流动连线。
