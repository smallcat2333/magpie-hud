# Feat_261019_2 分流图与托盘

> 应用：magpie-hud

## 1. 需求

### 1.1 背景

来源：用户于 2026-10-19 提报并提供 [实现说明](../spec/magpie-route-float-SPEC.md)。本 FEAT 对应 M2，依赖 [悬浮窗基础闭环](Feat_261019_1_悬浮窗基础闭环.md) 的 Tauri 窗口、文件监视、结构化事件与两行说明。M1+M2 是优先交付的可视化 MVP。

用户希望看清“Agent → magpie → 命中账号”的流向，并通过托盘管理这个常驻监视窗口。只做简化分流图，不复刻完整 Routing 页、多账户座位、分组或规则编辑器。遵守 M1 的只读约束，不为获取图中候补账号读取账号配置、密钥或请求 HTTP API。

### 1.2 目标

在窗口上方显示三节点 SVG 流向图，收到新的路由记录时以粉/洋红色连线短暂高亮；下方保留 M1 的固定两行说明。提供托盘显示、隐藏和退出入口。

功能范围：

- 左节点显示记录中的 Agent（如 Claude Desktop），副标题显示请求模型 `req`；中节点为 `magpie`，副标题显示默认 `127.0.0.1:3425`，M3 接入显示配置；右节点显示当前命中账号及实际服务模型，字段来源沿用 M1 核实后的结构化结果。
- 使用 SVG 贝塞尔曲线连接三个节点，命中路径使用粉/洋红色。每条新有效记录触发 200–400ms 高亮动画，结束后保持命中态；同一去重记录不重播，快速连续记录以最新结果为准，不残留旧账号高亮。
- 图与两行文字使用同一份路由快照，避免账号、模型和文案错配。缺字段按 M1 降级，不把 `req` 当作已验证的服务模型。
- MVP 不画全部候补账号；SPEC 允许的 1–2 个灰色占位属于可选项，本轮不安排实现。
- 托盘菜单具备显示窗口、隐藏窗口、退出；隐藏后后台监视继续，重新显示时呈现最新有效状态；退出结束应用及后台监视。窗口失焦持续显示。
- 保持中文、深色主题、清晰可读，长账号/模型不撑破节点与底栏。具体布局及动效设计在 §2 定稿。

### 1.3 验收标准

- [ ] 真实有效记录到达后，三节点显示 Agent/req、magpie/显示地址、命中账号/服务模型；图与底部两行对应同一路由快照，缺字段遵循 M1 降级，底栏始终维持两个信息槽。
- [ ] 每条新有效记录的命中连线呈粉/洋红高亮，动画持续 200–400ms 后保留命中态；重复记录不重复播放，连续不同账号记录最终停在最新账号，加入动画后仍满足完整记录写入至内容更新 ≤500ms。
- [ ] 托盘可显示、隐藏、退出；隐藏期间写入新 fixture 记录后重新显示能看到最新状态，失焦不关闭，退出后进程和文件监视停止。
- [ ] Windows 实际 WebView 中长账号/模型不破坏布局；空态、缺文件和解析失败保留 M1 约定，图中不编造候补账号或排除原因；README 增补托盘使用说明及实际运行截图。

### 1.4 初步路线

复用 M1 的 Tauri 窗口、`route-update` 快照与原生 HTML/CSS/JS，用 SVG 三节点和贝塞尔连线实现图形；动画只响应去重后的新结果。托盘复用 Tauri 2 的系统托盘和菜单能力，不另起进程或第二套监视器。

由首个 FEAT 的 UI 阶段确定整窗总纲，本 FEAT 只深化上方图形与托盘交互；具体组件和事件拆分留给开发阶段。验证重点是连续更新时图文一致、隐藏/显示生命周期和退出清理。位置保存、多屏/DPI 和工作区约束由 [多屏与配置](Feat_261019_3_多屏与配置.md) 收口。
