## 1. 需求

### 1.1 背景

来源：用户于 2026-10-19 提报并提供 [实现说明](../spec/magpie-route-float-SPEC.md)。本 FEAT 对应 M2，依赖 [悬浮窗基础闭环](Feat_261019_1_悬浮窗基础闭环.md) 的 Tauri 窗口、文件监视、结构化事件与两行说明。M1+M2 是优先交付的可视化 MVP。

用户希望看清“Agent → magpie → 命中账号”的流向，并通过托盘管理这个常驻监视窗口。只做简化分流图，不复刻完整 Routing 页、多账户座位、分组或规则编辑器。遵守 M1 的只读约束，不为获取图中候补账号读取账号配置、密钥或请求 HTTP API。

### 1.2 目标

在窗口上方显示三节点 SVG 流向图，收到新的路由记录时以粉/洋红色连线短暂高亮；下方保留 M1 的固定两行说明。提供托盘显示、隐藏和退出入口。

功能范围：

**2026-10-20 用户增量，覆盖下述早期单账号布局：** 左侧增加按本地日期的 Token、费用记录和 Tks，右侧改为模型方形图标及两行矩形路由块（缩略账号 / 会话短号＋模型＋强度），扩大可用空间。支持通过完整 `session` ID 分组并选择会话，缺 ID 明示“未标记会话”；默认显示最近三个会话。显示真实 HTTP 失败、调用方取消、后续成功恢复或重试成功，不推测日志未记录的冷却时间。`usage.jsonl` 当前未提供逐次失败账号与冷却秒数，所以不能复刻原生路由页实时倒计时。

统计口径：当日完成请求按 `t` 转系统本地日期归属；Token=`in+out+cache_read`，不含 `kind=routing` 分类器请求；费用只累计带 `credits` 的记录并明示 Credits 与覆盖条数，无数据为“未记录”，不推算美元；Tks=`Σout/Σ(ms−ttft_ms)×1000`，仅纳入成功且时长有效的记录。启动 64KB 分块流式扫描，运行中读取新增字节，取代早期只能看到最后 64KB 的方式。


- 左节点显示记录中的 Agent（如 Claude Desktop），副标题显示请求模型 `req`；中节点为 `magpie`，副标题显示默认 `127.0.0.1:3425`，M3 接入显示配置；右节点显示当前命中账号及实际服务模型，字段来源沿用 M1 核实后的结构化结果。
- 使用 SVG 贝塞尔曲线连接三个节点，命中路径使用粉/洋红色。每条新有效记录触发 200–400ms 高亮动画，结束后保持命中态；同一去重记录不重播，快速连续记录以最新结果为准，不残留旧账号高亮。
- 图与两行文字使用同一份路由快照，避免账号、模型和文案错配。缺字段按 M1 降级，不把 `req` 当作已验证的服务模型。
- MVP 不画全部候补账号；SPEC 允许的 1–2 个灰色占位属于可选项，本轮不安排实现。
- 托盘菜单具备显示窗口、隐藏窗口、退出；隐藏后后台监视继续，重新显示时呈现最新有效状态；退出结束应用及后台监视。窗口失焦持续显示。
- 保持中文、深色主题、清晰可读，长账号/模型不撑破节点与底栏。具体布局及动效设计在 §2 定稿。

### 1.3 验收标准

- [ ] 真实有效记录到达后，三节点显示 Agent/req、magpie/显示地址、命中账号/服务模型；图与底部两行对应同一路由快照，缺字段遵循 M1 降级，底栏始终维持两个信息槽。
- [ ] 每条新有效记录的命中连线呈粉/洋红高亮，动画持续 200–400ms 后保留命中态；重复记录不重复播放，连续不同账号记录最终停在最新账号，加入动画后仍满足完整记录写入至内容更新 ≤500ms。
- [ ] 托盘可显示、隐藏、退出；隐藏期间写入新 fixture 记录后重新显示能看到最新状态，失焦不关闭，退出后进程和文件监视停止。
- [ ] Windows 实际 WebView 中长账号/模型不破坏布局；空态、缺文件和解析失败保留 M1 约定，图中不编造候补账号或排除原因；README 增补托盘使用说明及实际运行截图。

### 1.4 初步路线

复用 M1 的 Tauri 窗口、`route-update` 快照与原生 HTML/CSS/JS，用 SVG 三节点和贝塞尔连线实现图形；动画只响应去重后的新结果。托盘复用 Tauri 2 的系统托盘和菜单能力，不另起进程或第二套监视器。

由首个 FEAT 的 UI 阶段确定整窗总纲，本 FEAT 只深化上方图形与托盘交互；具体组件和事件拆分留给开发阶段。验证重点是连续更新时图文一致、隐藏/显示生命周期和退出清理。位置保存、多屏/DPI 和工作区约束由 [多屏与配置](Feat_261019_3_多屏与配置.md) 收口。

## 2. 原型（活文档：UI 设计贯穿始终，随 dev 演进）

### 2.1 设计总纲

2026-10-20 现行界面以 `ui/index.html`、`ui/hud.css`、`ui/hud.js` 为准；本节下方早期单账号建议作为历史保留，不再描述现行布局。当前 1120×400，最左 156px 为当日统计，中间为来源与 Magpie，右侧占余下空间展示两行路由块；顶部会话选择，底部固定两行。最近会话视图最多三个会话，单会话可展示最新路由和有记录依据的失败账号。图标使用本地 LobeHub SVG，未知模型显示中性符号；长文字单行省略，完整内容保留提示。

沿用 [M1 §2 总纲](Feat_261019_1_悬浮窗基础闭环.md) 与 [统一 HTML 原型](../ui/magpie-hud.html)，用户已于 2026-10-19 授权 UI 自行设计。本 FEAT 只深化图形与托盘，不另建页面，不复刻候补账号列表。

上方图形由五列组成：来源文字、左贝塞尔连线、magpie 中枢、右贝塞尔连线、命中账号。左右连线 2px，端点 ≥8px；账号框左侧洋红短线与对号同时表达命中，颜色不作为唯一线索。账号名和服务模型单行省略，悬停/聚焦节点保留完整内容。时间与统计仍在底部两行，不新增 KPI 卡片。

静态命中路径用 `#E064A2`，新记录仅播放 320ms 沿线闪光后保持命中态；不常驻脉冲。系统设置减少动态效果时取消闪光，仍更新内容和静态路径。深色背景和文字 token 与 M1 一致，图形中的文字使用文字色而非路径色。

托盘使用 Tauri 原生菜单，顺序为“显示窗口”“隐藏窗口”、分隔线、“退出”。顶部“隐藏到托盘”与此使用同一行为。原型外围的“托盘菜单”仅为结构演示，不作为真正的系统托盘验收。

### 2.3 交互说明

- 仅在去重后的新有效快照到达时同步替换图与两行，取消前次尚未结束的动画后播放新动画；实际更新速度不能被动效延迟。
- 重复记录不重播；连续不同账号后右侧只保留最新账号。隐藏期间不靠动画通知用户，恢复时显示最新快照，不回放隐藏期间的历史动画。
- 空态灰显路径/端点、右侧显示“尚无命中账号”；解析异常保留上一有效快照，顶栏轻提示，不能把解析失败误画成新成功命中。
- 隐藏窗口后后台监视继续，失焦不隐藏；托盘“显示窗口”恢复最近快照并交给 M3 校核工作区；“退出”停止后台任务和应用。
- 原型菜单按钮可键盘聚焦，Escape 或点击外围收起；原生菜单交互由 Tauri/Windows 负责。原型“退出”只模拟，不宣称关闭了真实进程。

### 3.2 开发记录

### 2026-10-19 [T4] 分流图与托盘
- 方案：产品界面复用 M1 快照和 SVG；托盘使用 Tauri 原生菜单。
- 结果：图文同一快照更新，新记录播放 320ms，减少动态效果时跳过；托盘提供显示、隐藏、退出。系统托盘视觉尚未人工确认。

### 2026-10-20 [T7] 会话路由与当日统计
- 来源：用户提供路由页和悬浮窗截图，明确要求直接实现失败恢复表现、模型图标矩形块、账号缩略、模型与强度、扩大右侧，以及当日 Token/费用/Tks 与按会话查看。
- 方案：`usage.rs` 维护当日会话账本与真实状态，`tail.rs` 流式启动和增量读取，`lib.rs` 缓存统一快照；WebView 以本地 HTML/CSS/JS 和 SVG 渲染，不读密钥、不调用路由 HTTP API。
- 结果：两行路由块、最近三个会话/单会话选择、同步统计和底部说明、真实失败与取消、后续恢复/重试成功；费用仅 Credits 覆盖，冷却倒计时未记录则不推测。并发完成按追加顺序，日界归属按本地 `t`。
- 验证：9 项 Rust 测试、JS 语法、调试构建通过；真实 Tauri WebView2 脱敏日志测试覆盖会话选择、503→200 恢复、半行不入账、费用覆盖和图片加载，最终完整写入到渲染约 139ms，进程正常退出。浏览器 1120×400 与 720×400 无横向溢出，固定两行。
- 遗留：真实日志不含逐次失败尝试的账号和冷却秒数，不能提供原生路由页相同的精确恢复倒计时；正式费用账单需另行明确金额/价格来源。
