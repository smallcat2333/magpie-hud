## 1. 需求

### 1.1 背景

来源：用户于 2026-10-19 提报并提供 [实现说明](../spec/magpie-route-float-SPEC.md)。本 FEAT 对应 M3，在 [悬浮窗基础闭环](Feat_261019_1_悬浮窗基础闭环.md) 和 [分流图与托盘](Feat_261019_2_分流图与托盘.md) 基础上补齐常驻悬浮窗的多屏与配置体验。

目标环境为 Windows 10/11，需适应三屏和不同 DPI。用户要求位置记忆、窗口不越界且不盖任务栏；M1+M2 虽为优先交付项，但不能以完成它们代替这组完整产品验收。rs_agent_router 只作为多屏/任务栏行为参考，不合并代码、不修改该仓库。

### 1.2 目标

保存悬浮窗的位置与尺寸，在启动、跨屏移动、显示器/DPI 变化和工作区变化后，保证窗口留在所在显示器的可用工作区内。配置支持自定义 usage 路径、仅供显示的 Magpie 地址和置顶开关。

功能范围：

- 配置存储在 `%APPDATA%\magpie-hud\config.json`；这是将 SPEC 的示例目录 `magpie-route-float` 对齐用户已指定的产品目录名。路径按当前用户主目录和系统应用数据目录解析，不写死开发机用户名。
- 配置项仅包含 `usage_jsonl_path`（可空，使用默认 `%USERPROFILE%\.config\magpie\usage.jsonl`）、`magpie_host`（默认 `127.0.0.1:3425`，仅用于节点显示）、`window` 位置尺寸、`always_on_top`（默认 true）。位置尺寸的坐标单位和落盘结构在开发阶段固定，避免物理像素与逻辑像素混用。
- 记住正常退出前的窗口位置/尺寸，重启恢复；恢复坐标失效、原显示器断开或工作区缩小时，调整回当前可用工作区，窗口保持可见。首次运行无配置使用约定默认值，损坏/非法的外部配置须给出可见错误或明确恢复提示，具体处理在开发阶段确认，不静默忽略。
- 以显示器工作区而非完整屏幕边界约束窗口，处理负坐标显示器和不同 DPI。移动/跨屏后收敛到对应工作区，不长期压住任务栏；显示/恢复和显示器变更时重新核对，不把拖动前的屏幕当作固定边界。
- 若后续 UI 产生展开内容，下半屏优先向上展开，仍受同一工作区约束；当前无展开内容时不额外新增面板。角落缩放为 SPEC 可选项，本轮不承诺新增。
- 文案打磨仅完善 M1 的真实字段格式、时间与缺字段降级，不新增 HTTP API、完整排除原因推断或账号读取。
- 安装器、开机自启与 HTTP 增强均为后续可选项，本 FEAT 不默认启用。只保证 `cargo tauri build` 可生成 Windows 构建产物，不额外承诺新的安装流程。

### 1.3 验收标准

- [ ] 首次运行无配置可启动；改变位置/尺寸并正常退出后重启，位置/尺寸可恢复；配置文件位于当前用户应用数据目录，内容只有约定设置，不含 API key、原始 usage 记录或账号凭据。
- [ ] 三屏及不同 DPI 下，拖动跨屏、显示/隐藏恢复、重启恢复和工作区变化后，整个窗口位于相应工作区内，不长期压住任务栏；覆盖负坐标显示器和旧位置对应显示器断开的情况，未具备真实设备时明确登记未验证项。
- [ ] 设置自定义 `usage_jsonl_path` 后使用该文件且保持 M1 的监视/降级行为；空值回到默认路径；修改 `magpie_host` 只影响显示、不发起 HTTP 请求；`always_on_top` 默认 true，设置为 false 后能取消置顶。
- [ ] 工作区小于保存尺寸、配置非法和来源文件消失时没有不可见/无法操作的窗口或静默假成功；有效日志仍保持时间格式和两行限制，文件不存在和解析错误遵守 M1 规定。
- [ ] README 说明配置位置、字段含义、启动和 `cargo tauri build`，附最终运行截图及多屏/DPI 实测记录；逐项汇总 M1/M2/M3 的通过项与未验证项，不将可选开机自启、安装器或 HTTP 增强写成已实现。

### 1.4 初步路线

复用已有 Tauri 窗口与 Rust 状态管理，配置只围绕上述字段落盘；通过 Tauri 的屏幕/坐标能力实现位置恢复，Windows 工作区信息优先使用框架现有能力，不足时才使用平台原生 API。实现前核对真实 API 的坐标单位与 DPI 语义，不在需求阶段预写未经验证的接口。

只读参考 rs_agent_router 现有悬浮窗的工作区行为，不将其实现直接揉入项目。具体参考位置、复用判断和配置/窗口模块拆解留到 §3。

先验证确定性的坐标换算、边界夹取和配置解析，再在真实多屏/DPI 环境验证拖动、恢复与任务栏边界。性能要求仍沿用完整记录写入至界面更新 ≤500ms，避免位置持久化阻塞文件监视和前端刷新。

## 2. 原型（活文档：UI 设计贯穿始终，随 dev 演进）

### 2.1 设计总纲

沿用 [M1 UI 总纲](Feat_261019_1_悬浮窗基础闭环.md) 和 [统一 HTML 原型](../ui/magpie-hud.html)，不新增设置页。默认 840×280 逻辑像素，优先支持 720px 宽度；所有工作区计算必须统一物理像素与逻辑像素，不能把 CSS 像素直接当 Windows 工作区像素。

本 FEAT 的 UI 重点为窗口行为：初次展示、从托盘恢复、重启、跨屏与工作区变化时保持整窗可见；根据当前所在屏工作区布局，不盖任务栏。现阶段不增加向下展开区，因而不引入方向切换面板；未来有展开需求时遵守下半屏向上展开规则。

置顶按钮直接显示 `always_on_top` 状态。`usage_jsonl_path` 和 `magpie_host` 仍由本地配置提供，不为这些字段新增编辑页、路径选择器或开机自启入口。路径只在空态底部第二行显示，正常路由时让位于说明；地址在中间节点副标题显示。非法配置通过顶栏警示与固定两行提示可定位的问题，不弹出一套新的全屏错误页面。

### 2.3 交互说明

- 启动后读取配置，先确定工作区与允许尺寸再显示窗口；保存位置在失效显示器或屏幕外时先修正再展示，防止启动后找不到。
- 拖动跨屏结束、托盘恢复、DPI/显示器/工作区变化后重新约束整窗边界，原显示器被拔除时回到可见工作区。小工作区优先缩到可用范围，不能只夹取左上角而留右/下边越界。
- 保存和恢复位置尺寸不触发页面跳转，不阻塞路由刷新；置顶按钮先反映实际窗口状态，失败不能只更换图标冒充成功。
- 路径配置为空使用默认用户目录，文件缺失在两行区域说明；`magpie_host` 只影响文本，不发网络请求。非法配置在窗口可见位置明确报错，保留可操作的窗口，开发阶段核对具体错误语义。
- 原型的 720px 开关只验证排版意图，不能代替真实 DPI、工作区或原生缩放验证；不据此勾选 §1 的多屏验收。
