## 1. 目标
### 1.1 优化对象与动机
用户反馈用量详情重置周期的实际使用估值、窗口估值和历史统计长时间加载。检查逐周期查询及逐请求费用分页的重复工作，保持原始请求身份匹配、费用覆盖及筛选口径。

### 1.2 验收阈值（量化）
- 同一固定日志、四个周期、同一模拟网关的三次中位数：全部周期加载时间和费用分页请求数均至少降低50%。
- 相同筛选重绘/切换指标不新增周期费用请求；统计与优化前逐项一致。
- 真实只读接口以相同日期分别测全量和账号约束分页，记录接口本身的等待成本，不将模拟成绩当作生产耗时。

## 2. 基线
- 初步实测：日志15,355,121字节；2026-10-24逐请求第一页500条，总3431条，约0.772秒。真实接口三次测量（2026-10-18..23）全量20,307条/41页，单页中位0.130秒；provider=codex+account筛选6,616条/14页，单页中位0.123秒（首轮分别2.710/1.586秒）。接口支持provider/account过滤，已核对上游usageapi.FilterOf。固定模拟网关对比见§3。
- 当前前端最多并发2个周期查询，每个查询扫描全日志，费用接口只限制日期。周期所属账号尚未用于缩小请求范围。

## 3. 优化记录
### 2026-10-24 周期账号约束下推费用接口
- 依据：前端周期查询仅使用全局筛选，没有周期自身的供应商/账号；Rust只在本地过滤行，费用分页仍读取日期内所有账号。
- 改动：ui/details.js为每个周期查询携带其provider/account身份，保留其他筛选；src-tauri/src/details.rs仅当待匹配行共有同一非空provider/account时，URL编码下推对应网关条件。同一查询复用HTTP客户端。多账号场景不强行缩窄。原身份核对、冲突去重、未知费用、读取预算不变。
- 固定口径：10,000条/2,756,454字节，4个不重叠周周期，各500条目标账号+2000条其他账号；模拟每页80ms，2个周期并发，3次中位。
- 对比：0.942604秒 → 0.298209秒（降低68.36%）；20页 → 4页（减少80%）。三次各请求明细/Token/逐请求费用/警告的SHA256均为d0a7588960225882289058d846f6a58679a1cabc6ae24695945608424250ccc4。
- 真实完整分页同一历史范围三次对比：全量41页，中位68.617秒（68.946/68.617/55.536）；账号约束14页，中位17.364秒（17.497/17.358/17.364），降低74.69%。两种方式均取得6616条目标记录，逐请求金额及priced状态指纹全部相同（7f13b1cf6437d18abea0a6356025041546373ad10e919cb03459889900b6d05c）。这只计网关费用分页，不含本地扫描和UI。最终构建固定基准复测中位0.292195秒/4页，输出指纹仍与基线一致。

## 4. 正确性验证
- 74项Rust测试通过，覆盖多账号不缩窄、中文/+/@/&账号URL编码；既有费用去重/冲突/0/未知/周期边界测试通过。
- 原生IPC固定输入优化前后三次完整输出指纹一致。原生周期界面4行均500次/实际0.50美元/窗口1.00美元，加载标记0；费用页共4次，切换指标/周期/趋势后无新增请求。初始化就绪后才驱动点击，避免测试脚本过早点击产生空表误判。
- DetailFilters显式camelCase解析sourceKeys/accountKeys；周期异步行统一补accountKey，账号筛选保持与初次查询同口径。
- 浏览器四周期加载完成后切换费用/调用指标、上一周期、趋势与周期页签，请求数5→5，加载单元格为0，控制台无错误。

## 5. 结论
采用周期账号约束下推及查询内客户端复用；不增加并发、不引入跨刷新旧费用缓存。已达固定口径阈值。真实接口分段对比和最终原生周期表复测通过，已更新桌面运行版本，保留主窗位置/尺寸/置顶状态。不提交、不写README；人工确认留待用户。
