# Perf_261108_1 WebView 持续渲染开销

> 状态：已关闭
> 应用：magpie-hud
> 创建：2026-11-08　　关闭：2026-11-08

## 1. 目标
### 1.1 优化对象与动机
用户提供 HF-459（2026-11-08 17:09–17:20）采样：HUD 的 WebView2 子进程合计约 194% CPU，整机周期性卡顿。目标是降低 HUD 的持续渲染开销，保留可见窗口的动画外观、流速、布局和统计行为。该报告为问题线索，不视为本次同口径基线，也不据此认定所有系统停顿均由 HUD 导致。

### 1.2 验收阈值（量化）
- 代表性隔离场景：10 张会话卡、其中 6 个活动请求，715×1000 窗口，真实 Windows Release WebView2，动画保持开启。
- 相同场景 WebView2 子进程 CPU（100%=1 个逻辑核），3 次各 10 秒取中位：目标较本次基线降低至少 30%。
- 连线 1 秒循环、运行状态旋转 1.4 秒循环等既有时长不改变；卡片几何差异不超过 1 CSS px，统计文本一致。
- 同时采集当前生产实例进程树作归因参考；其真实请求变化不适合作为严格 A/B 依据。

## 2. 基线
- 方法：psutil CPU 时间差 / 墙钟时间；只统计指定 HUD PID 的后代，分别记录 renderer、GPU、browser、utility 与 Rust 主进程。WebView2 辅助进程数不等同于页面实例数。
- 环境：Windows 11，WebView2/Chromium 157，20 逻辑核 / 12 物理核，DPR=1，可用内存约 21.5 GiB。同版本隔离 WebView 的 `SystemInfo.getInfo`：`glRenderer=ANGLE (NVIDIA GeForce GTX 1080, Direct3D11)`，`gpu_compositing=enabled`、`rasterization=enabled`、`directComposition=true`，未回退软件渲染。GPU 进程的 CPU 百分比不是显卡利用率。采样时整机另有其他负载（一次读数 80.9%），绝对值仅适用于该环境。
- 生产实例参考：两段 10 秒 WebView2 合计 139.29% / 125.52%；GPU 84.57% / 75.59%，renderer 49.12% / 44.17%，Rust 主进程 6.53% / 9.18%。该轮第三段未完成，不用于三次中位统计。
- 合成场景正常运行，3×10 秒：109.54% / 98.94% / 99.27%，中位 **99.27%**。单个 renderer；browser、GPU、crashpad、两个 utility 是辅助进程，并非六个页面。
- 约 30 秒 DevTools Performance 指标增量：TaskDuration=5.767s，ScriptDuration=0.095s，LayoutDuration=0.203s，RecalcStyleDuration=1.200s，LayoutCount=1183，RecalcStyleCount=5119。说明单纯 JS 执行不是主要耗时。
- 仅用于归因的临时 CSS 消融（各 3×5 秒中位）：移除 CSS 模糊 94.92%；暂停 SVG 流动虚线 38.86%；暂停全部 CSS 动画 8.96%。消融均未写入产品源码，不作为最终方案。

## 3. 优化记录
### 2026-11-08 绘制消融与候选比较（尚未修改产品代码）
- 依据：正常活动动画约 99.27% WebView CPU；暂停流动虚线降至 38.86%，ScriptDuration 仅约 0.095s/30s。主因方向为持续 SVG paint / 合成，不将后台 Rust 轮询认定为这段样本的主要来源。
- 第二轮诊断均为 3×5 秒：正常 91.09%；全部 SVG 合成图层 79.16%；SVG paint containment + 合成图层 76.30%；整个 content 分层 104.33%；按 path 强制图层 85.71%；仅将流动虚线采样为每秒 30 步 64.88%。不同轮整机负载有变化，只作候选筛选，最终仍以原场景 3×10 秒对比验收。
- 30 步保持 1s 循环和每圈 28px 位移，每步约 0.93px；不停止流动，不改曲线、颜色、线宽或卡片动画。是否采用仍待组合验证。
- 暂停 spinner 的第一轮选择器使用 `.state-spinner`，产品实际为 `.request-spinner`，该项消融无效，不将其结论作为证据。
- 流程图：无（当前候选仅 CSS 绘制/合成策略，无业务执行流程变更）。

### 2026-11-08 最终采用：局部连线绘制 + 亚像素步进
- 改动：`ui/hud.css` 给 `#route-lines,#source-lines` 添加 `contain:paint;transform:translateZ(0)`；流动虚线设为 `steps(30,end)`。产品绘制规则新增 2 条，没有改变 Rust 采集逻辑、字体、卡片宽度、模型名优先级或磨砂。
- 状态转圈继续使用原来的 1.4s linear，不采用对 spinner 的降采样试验；不采用收益不稳定的背景拆层/去掉模糊/去掉 vector-effect。
- 最终测量使用真正编译的旧/新 Release 二进制，不注入诊断 CSS。依次运行旧→新→旧，每组 3×10 秒，10 卡 / 6 活动请求 / 715×1000 / DPR1，GPU 后端一致。

- GPU 进程仍有 CPU 开销是正常的驱动/提交工作；硬件加速已开启。此次降低持续重绘频率，不声称把所有 SVG 工作搬到 GPU。

## 4. 正确性验证
- Node 前端现有 7 组回归全部通过（包含数据源/服务器时钟、详情分页、费用缓存、履历刷新）。本次业务逻辑无修改。
- Release 桌面构建通过。
- Browser 预览的合成场景确认 `contain:paint`、1s 连线循环及 `steps(30)` 生效，状态转圈仍为 1.4s，CSS 模糊仍为 22px。首次以普通站点地址打开时 capabilities 返回 404；切到 `?preview=1` 后使用纯合成事件，不把初次静态服务器不提供 API 视为产品错误。
- 原生 Release 对比：10 张卡片的 x/y/width/height 最大差异 **0 CSS px**；SVG 路径 `d` 完全一致，线色/线宽完全一致，统计文本一致；所有连线循环时长一致，状态转圈仍 1.4s，模糊仍 22px。
- 唯一有意的时间采样变化：虚线每秒 30 步，每步约 0.93px；保留每秒 28px 的平均流速及首尾无缝。不能将静态几何相同解读为所有动画帧逐像素相同。

## 5. 结论
- 保留两个连线绘制规则，1.0.33 同场景 WebView CPU 中位数降低约 42.9%，视觉/行为几何检查通过；未改变此前被用户要求撤回的模型名/路径省略顺序。
- 本机原启动路径已替换并重启至 `Magpie HUD V.1.0.33`，保留生产配置和 1.0.32 可执行文件备份。未开启生产调试端口。
- 重启后生产实例另测 3×10 秒：WebView CPU 118.05% / 105.21% / 95.90%，中位 105.21%。该期间实际会话与整机负载会变化，不能用它与最早两段生产采样计算严格改善百分比；42.9% 来自上述隔离 A/B/A 对照。
- 本次证实并降低 HUD 持续绘制开销，没有运行完整 10 分钟整机复测，不能据此声称 Magpie、其他 WebView 或编译负载导致的所有周期卡顿都已消失。
