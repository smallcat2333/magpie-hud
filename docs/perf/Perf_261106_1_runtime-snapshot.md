## 1. 目标
### 1.1 优化对象与动机
处理 issue 4：concurrency 每 500ms 刷新时，Runtime 全局锁内重复检查日志并执行完整 UsageLedger::snapshot，阻塞窗口状态操作。共享工作区已有其他功能改动，本次保留它们。

### 1.2 验收阈值（量化）
- 固定 100,000 条脱敏记录、1,000 个会话，release 构建，同机三组中位数：无新日志刷新耗时降低至少 90%。
- 扫描/聚合不持 Runtime 锁；用同步屏障阻塞账本锁时，窗口状态读取在 100ms 内完成。
- 无变化重复刷新不重建账本统计；追加、坏行、轮转、缺失恢复、跨日和配置错误正确更新，实时活动与费用/额度仍更新。

## 2. 基线
- 口径：Windows 本机；Rust ignored 基准 `runtime_snapshot_benchmark`，100,000 条 JSONL、1,000 会话；首次真实文件读取后，每组 5 次无变化刷新，共 3 组；另测更新时竞争 Runtime 锁的等待时间。
- 数据：24,477,890 字节；首次读取与发布 1,683.960ms；每次无变化刷新三组均值 721.416 / 762.793 / 808.513ms，中位 762.793ms。快照规范化 JSON 的 FNV-1a 指纹 `33e7dd0e421dd800`（固定本地日期/时区；仅用于同日输出对比）。
- 热点证据：文件不变仍每次进入 UsageLedger::snapshot 的全记录分组、卡片、agent_groups 和 model_usage 路径；单次耗时超过 concurrency 的 500ms 轮询间隔。

## 3. 优化记录
### 2026-11-06 独立账本锁与按修订号复用统计底稿
- 依据：10 万条记录下，无变化刷新仍完整遍历 records，Runtime 锁覆盖文件读取、分组、卡片与模型汇总，三组中位 762.793ms。
- 改动：新增 `src-tauri/src/reader.rs`，让日志游标、账本和缓存使用独立锁。缓存键包含 ledger revision、最早有效日期、缺失状态、日志路径、host 和配置错误；不缓存实时活动、额度、费用或连接故障。
- 改动：`lib.rs` 的日志 watcher 在 Runtime 锁外读取和聚合，之后替换 Arc 底稿，再叠加当前实时状态；concurrency、trace 和遥测刷新只复制底稿。事件序列化与发送在释放 Runtime 锁后执行，前端已有 revision 检查忽略过期事件。
- 改动：模型费用行复制移入 spawn_blocking，先释放 Runtime 锁，再使用独立账本锁；日期与对应账本在同一锁下取得。
- 对比：同一 24,477,890 字节样本，首次优化测得 762.793ms → 9.410ms；复测中位 9.735ms。最终源码三组 9.454 / 10.220 / 11.103ms，中位 **10.220ms**，相对基线降低 **98.66%**；每次输出指纹均一致。
- 大账本竞争：在同一 10 万条记录上逐轮追加 1 条完成记录，后台运行真实 refresh_log；另一线程每隔 1ms 取得 Runtime 锁并更新窗口几何状态。三轮最大等待 **17.037 / 17.423 / 19.165ms**，均低于 100ms 目标。它衡量 Rust 状态锁等待，不包含操作系统绘制、WebView 帧率或原生鼠标事件延迟。
- 首次读取：基线 1,683.960ms；优化后各次观测 1,941.014 / 1,541.901 / 1,797.116ms，未作为性能提升证据。本次目标是移出全局锁并取消无变化时的重复聚合，未优化首次全量扫描算法。
- 流程图：无（仓库没有 docs/flow 相关图）。
